Usage Examples
==============

Each workflow below uses a fixture bundle from the test suite and shows the
exact invocation together with the resulting output. Successful runs are
quiet on stderr unless a warning applies. Runs that resolve XSD schemas use
a local schema cache; point ``xsd_cache_dir`` at a writable directory (see
:doc:`config`) to avoid repeated downloads.

Workflow 1: a basic index file
------------------------------

Generate an index file from the single-label ``simple_pds_only`` bundle
using a ``columns:`` configuration::

    pds4_create_xml_index generate_index_file \
        --bundle-root tests/data/bundles/simple_pds_only \
        --config-file tests/data/configs/simple.yaml \
        --output-file index.csv \
        '**/*.lblx'

The command writes ``index.csv``::

    LID,FILE_NAME,TITLE
    urn:nasa:pds:test_simple:index:row1,row1.lblx,Row 1

It also writes ``index.lblx``. The field definition for the first column is::

    <Field_Delimited>
        <name>LID</name>
        <field_number>1</field_number>
        <data_type>ASCII_LID</data_type>
        <maximum_field_length unit="byte">35</maximum_field_length>
        <description>XPath: lid</description>
    </Field_Delimited>

Workflow 2: multiple namespaces
-------------------------------

The ``multi_namespace`` bundle mixes the ``pds``, ``geom``, and ``rings``
namespaces. The configuration selects columns from all three::

    pds4_create_xml_index generate_index_file \
        --bundle-root tests/data/bundles/multi_namespace \
        --config-file tests/data/configs/multi_namespace.yaml \
        --output-file index.csv \
        '**/*.lblx'

The resulting ``index.csv`` has one row per label::

    LID,FILE_NAME,TITLE,GEOM_METHOD,RING_NAME
    urn:nasa:pds:test_multi_ns:index:row_a,a.lblx,Row A,row_a_method,row_a_ring
    urn:nasa:pds:test_multi_ns:index:row_b,b.lblx,Row B,row_b_method,row_b_ring
    urn:nasa:pds:test_multi_ns:index:row_c,c.lblx,Row C,row_c_method,row_c_ring

Workflow 3: fixed-width output
------------------------------

Setting ``output.fixed_width: true`` pads every column to its maximum
value width so the columns align::

    pds4_create_xml_index generate_index_file \
        --bundle-root tests/data/bundles/simple_pds_only \
        --config-file tests/data/configs/fixed_width.yaml \
        --output-file index.csv \
        '**/*.lblx'

Because this bundle has a single data row, each value already occupies its
column's maximum width, so the emitted ``index.csv`` is::

    LID,FILE_NAME,TITLE
    urn:nasa:pds:test_simple:index:row1,row1.lblx,Row 1

Workflow 4: CRLF line endings
-----------------------------

Setting ``output.line_ending: CRLF`` terminates every record with a
carriage-return and line-feed pair instead of a bare line-feed::

    pds4_create_xml_index generate_index_file \
        --bundle-root tests/data/bundles/simple_pds_only \
        --config-file tests/data/configs/crlf.yaml \
        --output-file index.csv \
        '**/*.lblx'

The bytes of ``index.csv`` are the same as Workflow 1 except that each line
ends with ``\r\n``::

    LID,FILE_NAME,TITLE\r\n
    urn:nasa:pds:test_simple:index:row1,row1.lblx,Row 1\r\n

Workflow 5: fail-slow mode
--------------------------

The ``multi_lid`` bundle contains three labels that share a logical
identifier. By default the run stops at the first duplicate; ``--fail-slow``
scrapes every label, logs each eligible error as a warning, and summarizes
the count before exiting with code ``2``::

    pds4_create_xml_index generate_index_file \
        --bundle-root tests/data/bundles/multi_lid \
        --config-file tests/data/configs/simple.yaml \
        --fail-slow \
        --output-file index.csv \
        '**/*.lblx'

The run reports the accumulated errors on stderr::

    WARNING [cli] b.lblx: duplicate LID 'urn:nasa:pds:test_lid:index:dup_row' in b.lblx and a.lblx
    WARNING [cli] c.lblx: duplicate LID 'urn:nasa:pds:test_lid:index:dup_row' in c.lblx and a.lblx
    ERROR [cli] 2 errors
    b.lblx: duplicate LID 'urn:nasa:pds:test_lid:index:dup_row' in b.lblx and a.lblx
    c.lblx: duplicate LID 'urn:nasa:pds:test_lid:index:dup_row' in c.lblx and a.lblx

Workflow 6: generate a starter columns block
--------------------------------------------

Run ``generate_xpath_list`` to emit every discovered leaf XPath as a
``columns:`` block. A configuration supplying the required
``label_contents`` is still needed::

    pds4_create_xml_index generate_xpath_list \
        --bundle-root tests/data/bundles/simple_pds_only \
        --config-file tests/data/configs/simple.yaml \
        --output-file columns.yaml \
        '**/*.lblx'

The written ``columns.yaml`` begins::

    # Generated by pds4_create_xml_index generate_xpath_list.
    # Edit each `name:` (or delete unwanted entries), then merge this
    # `columns:` block into one of your --config-file YAMLs.
    columns:
      - xpath: pds:Product_Observational<1>/pds:Identification_Area<1>/pds:logical_identifier<1>
        name: pds:Product_Observational<1>/pds:Identification_Area<1>/pds:logical_identifier<1>

Edit each ``name:`` to a friendly header, delete the entries you do not
want, and merge the block into one of your ``--config-file`` YAMLs.

Workflow 7: copy the default configuration
------------------------------------------

Write a copy of the packaged default configuration so it can be customized::

    pds4_create_xml_index copy_default_config --output-file config.yaml

The command writes ``config.yaml`` beginning with::

    # Default configuration for pds4_create_xml_index.
    # Users override these via one or more --config-file arguments; user
    # settings are deep-merged onto these defaults (scalars/lists replaced,
    # dicts merged).

Pass ``--force`` to overwrite an existing destination.

Workflow 8: the programmatic API
--------------------------------

The same pipeline is available in Python through
:func:`~pds4indextools.cli.run_generate_index_file`, which takes a
:class:`~pds4indextools.cli.GenerateIndexFileArgs` and returns a
:class:`~pds4indextools.cli.GenerateIndexFileResult`:

.. code-block:: python

    from pathlib import Path

    from pds4indextools import (
        GenerateIndexFileArgs,
        run_generate_index_file,
    )

    result = run_generate_index_file(
        GenerateIndexFileArgs(
            bundle_root=Path('tests/data/bundles/simple_pds_only'),
            patterns=('**/*.lblx',),
            config_files=(Path('tests/data/configs/simple.yaml'),),
            output_file=Path('index.csv'),
        )
    )
    print(result.csv_path, result.rows_written)

The call writes the same ``index.csv`` and ``index.lblx`` as Workflow 1 and
returns the written paths and row and column counts. On failure it raises a
subclass of :exc:`~pds4indextools.errors.Pds4IndexError`.
