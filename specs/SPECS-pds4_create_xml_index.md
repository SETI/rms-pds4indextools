# pds4_create_xml_index — Design Specification

> **Status:** Draft for review.
> **Owner:** Robert S. French (SETI / RMS Node).
> **Repository:** [SETI/rms-pds4indextools](https://github.com/SETI/rms-pds4indextools).
> **Document location:** `SPEC.md` (repo root).

This specification defines the rewritten `pds4_create_xml_index` tool. It supersedes
the legacy implementation that lives under `legacy/`. Every numbered requirement (`R*`)
in this document has at least one corresponding test case (`T*`) listed in
[Section 24 — Test inventory](#24-test-inventory).

## 1. Overview

`pds4_create_xml_index` is a command-line tool (and importable Python library) that
scans a directory of PDS4 XML labels, extracts per-label metadata into a tabular
index file, and writes a paired PDS4 XML label that describes that index file. It is
distributed as the Python package `pds4indextools` published to PyPI as
`rms-pds4indextools`.

The tool exposes three subcommands:

1. `generate_index_file` — scrape a curated set of label files, project the discovered
   XPaths through the config's `columns:` list to short column headers, and write both
   a CSV-format index file and a `.lblx` PDS4 label describing it.
2. `generate_xpath_list` — perform the same scrape and emit a paste-ready YAML
   `columns:` block listing every distinct canonical XPath that was found, suitable
   for use as a starting point when authoring a config `columns:` list.
3. `copy_default_config` — copy the packaged default configuration YAML to a
   user-specified destination so it can be edited.

### 1.1 Goals

- Produce PDS4-compliant index CSV + label pairs that can be ingested by the PDS
  Engineering Node validation tools without modification.
- Be deterministic: identical input produces identical output, including row order,
  column ordering, and field widths.
- Provide useful, actionable error messages with file paths and line numbers.
- Support both variable-width (RFC 4180) and fixed-width CSV output, both readable
  by any standard CSV parser.
- Allow projects to share a single template and configuration across many bundles.

### 1.2 Non-goals

- This tool does **not** generate PDS4 collection-inventory products
  (`Product_Collection`). That is the role of a separate utility (the legacy
  `pds4_create_collection_product.py`).
- This tool does **not** validate label content against PDS4 schemas/Schematron;
  use the PDS Engineering Node validate tool for that. We do, however, download
  XSDs to resolve element data types.
- This tool does **not** modify, rewrite, or repackage the input label files.

## 2. Glossary

| Term | Meaning |
|---|---|
| Bundle root | The filesystem directory passed via `--bundle-root` that anchors all relative paths (label discovery, `filespec` derivation). |
| Label | A PDS4 XML metadata file describing a data product. |
| LID | A PDS4 logical identifier (e.g. `urn:nasa:pds:bundle:collection:product`). |
| LIDVID | A LID concatenated with `::` and the `version_id` value. |
| XPath | An XPath expression identifying an element within a label. In this tool, XPaths are normalized to a canonical form (see §10). |
| Mapping file | A user-authored text file that maps canonical XPaths to short column names and selects auto-columns. |
| Auto-column | A computed column whose value is derived from the label file's path or LID, not from a scraped XPath. The five recognized auto-columns are `lid`, `lidvid`, `filespec`, `filename`, `bundle_name`. |
| Index file | The CSV-format output of `generate_index_file`. |
| Index label | The `.lblx` PDS4 XML label describing the index file. Generated by PdsTemplate. |
| PdsTemplate | The `rms-pdstemplate` library that performs the label generation. |
| System default config | The `default_config.yaml` packaged inside `pds4indextools` (read via `importlib.resources`). |
| Fail-slow | A run mode (`--fail-slow`) in which fail-slow-eligible errors (R-ERR-001) are accumulated rather than raised. The run attempts to scrape every discovered label; non-eligible errors (e.g. network or cache failures) still abort immediately. If any fail-slow-eligible errors were accumulated, the run exits with code 2 before writing output. |

## 3. CLI grammar

### 3.1 Executable name and subcommand aliases

- **R-CLI-001** The console-script entry point is registered as `pds4_create_xml_index`
  in `[project.scripts]`. No hyphenated executable alias is registered.
- **R-CLI-002** Subcommand names are accepted in BOTH underscored and hyphenated
  forms. Internally, the hyphenated form is mapped to the underscored canonical
  form before dispatch:
  - `generate_index_file` ⇄ `generate-index-file`
  - `generate_xpath_list` ⇄ `generate-xpath-list`
  - `copy_default_config` ⇄ `copy-default-config`

### 3.2 Top-level invocation

```text
pds4_create_xml_index [--version] <subcommand> [SUBCOMMAND_ARGS...]
```

- **R-CLI-003** The only flag accepted before the subcommand is `--version`, which
  prints `pds4_create_xml_index <PEP 440 version>` to stdout and exits with code 0.
- **R-CLI-004** All other flags belong to a specific subcommand and must appear
  after the subcommand name. Argparse's standard subparser grammar is used; there
  is no shared parent parser visible before the subcommand keyword.
- **R-CLI-005** When the user supplies no subcommand, the program prints the
  top-level help and exits with code 2 (CLI usage error).

### 3.3 `generate_index_file` subcommand

```text
pds4_create_xml_index generate_index_file
    --bundle-root PATH
    [--config-file PATH ...]
    [--label-template PATH]
    [--output-file PATH]
    [--fail-slow]
    [-v | -vv | -vvv]
    PATTERN [PATTERN ...]
```

- **R-CLI-010** `--bundle-root` is required; its value MUST be an existing
  directory or a symlink to an existing directory (see R-FS-001). It is resolved
  to an absolute path before use.
- **R-CLI-011** One or more positional `PATTERN` glob arguments are required
  (`nargs='+'`). Globs are interpreted relative to `--bundle-root` using
  `pathlib.Path.glob()` (which follows symlinks; see R-FS-002). Multiple patterns
  are unioned and the resulting set is deduplicated by absolute resolved path
  (R-FS-003). A pattern that begins with the platform's path-anchor (i.e.
  is absolute) is rejected with a `CliError` and exit code 1; patterns
  MUST be relative to `--bundle-root`.
- **R-CLI-012** `--config-file` may be supplied zero, one, or many times
  (`action='append'`). Each path is resolved against the current working
  directory or treated as absolute. Files are loaded in the order given and
  overlaid on the system default (see §15.4).
- **R-CLI-014** `--label-template` is optional. If absent, the packaged default
  template is used (see §14.1). When supplied, the path is resolved against cwd.
- **R-CLI-015** `--output-file` is optional. If absent, the tool writes
  `./index.csv` (and `./index.lblx`); if either of those exists in the cwd at
  start of run, the basename is auto-numbered as `index_1.csv`/`index_1.lblx`,
  `index_2.csv`/`index_2.lblx`, etc., choosing the lowest free integer such that
  *neither* the CSV nor the label name collides. When supplied, the value is
  used verbatim (after extension handling, R-OUT-010..R-OUT-012); if the target
  CSV or label already exists it is overwritten and a WARNING is logged
  (R-OUT-013).
- **R-OUT-010** When `--output-file` ends in `.csv`, that exact path is the
  CSV output and the label is the same path with `.csv` replaced by `.lblx`.
- **R-OUT-011** When `--output-file` has no extension, `.csv` is appended;
  the label uses `.lblx` on the same stem.
- **R-OUT-012** When `--output-file` ends in any other extension (e.g.
  `.tab`), that extension is honored verbatim for the data file; the
  label uses `.lblx` on the same stem.
- **R-OUT-013** When the user supplies an explicit `--output-file` and
  either the target data file (whose extension may be `.csv`, `.tab`,
  or whatever was supplied) or the paired `.lblx` label file already
  exists at write time, the existing file is overwritten and a
  WARNING-level log message is emitted naming both target paths. Auto-
  numbering (R-CLI-015) only applies to the default `./index.csv` case
  and never to user-supplied paths.
- **R-CLI-016** `--fail-slow` is a boolean flag (default off). See §17.
- **R-CLI-017** `-v`, `-vv`, `-vvv` set the logging level to INFO, DEBUG, DEBUG
  (clamped) respectively. Default is WARNING (see §18).

### 3.4 `generate_xpath_list` subcommand

```text
pds4_create_xml_index generate_xpath_list
    --bundle-root PATH
    [--config-file PATH ...]
    [--output-file PATH]
    [--fail-slow]
    [-v | -vv | -vvv]
    PATTERN [PATTERN ...]
```

- **R-CLI-020** `--bundle-root`, `PATTERN`, `--config-file`, `--fail-slow`, and
  the verbosity flags behave identically to `generate_index_file`.
- **R-CLI-021** `--label-template` is NOT accepted by this subcommand
  (argparse rejects it with code 2 and the standard "unrecognized
  argument" message).
- **R-CLI-022** `--output-file` semantics for this subcommand mirror
  R-CLI-015 / R-OUT-010..R-OUT-013 with the YAML data file `.yaml`
  substituted for `.csv` and NO paired label file:
  - When omitted, the tool writes `./columns.yaml`. If that name is
    taken, the basename auto-numbers to `columns_1.yaml`,
    `columns_2.yaml`, …, choosing the lowest free integer.
  - When supplied, the path is used verbatim. If the supplied path
    has no extension, `.yaml` is appended; any other extension is
    honored verbatim. If the target file already exists at write
    time, it is overwritten and a WARNING-level log message is
    emitted naming the path. Auto-numbering applies ONLY to the
    default `./columns.yaml` case.

### 3.5 `copy_default_config` subcommand

```text
pds4_create_xml_index copy_default_config
    --output-file PATH
    [--force]
    [-v | -vv | -vvv]
```

- **R-CLI-030** `--output-file` is required.
- **R-CLI-031** If the destination already exists, the run fails with exit code 1
  unless `--force` is supplied (in which case the file is overwritten with a
  WARNING).
- **R-CLI-032** This subcommand does NOT accept `--bundle-root`, `--config-file`,
  `--label-template`, `--fail-slow`, or any positional patterns.

### 3.6 Help text

- **R-CLI-040** Both the top-level `--help` and each subcommand's `--help`
  include a multi-paragraph epilog with two or three concrete usage examples
  showing common invocations.
- **R-CLI-041** Help text uses American English spelling and one space between
  sentences (matches `documentation.mdc` rule §2).

## 4. Subcommand semantics — `generate_index_file`

This section describes the high-level pipeline. Per-step requirements are pinned
in subsequent sections (§7–§14).

### 4.1 Pipeline

1. **Parse CLI args** (§3.3). Resolve `--bundle-root` to absolute (R-FS-001).
2. **Load config chain** (§15). System default → each `--config-file` in order,
   deep-merged. Pydantic validates the merged result (R-CFG-010..R-CFG-052).
3. **Resolve output columns** from the merged config's `columns:` list
   (§7). A missing or empty `columns` list is a `ConfigError` and the
   run fails fast (§7).
4. **Discover label files**. Apply each `PATTERN` via
   `Path.glob()`; union the matches; dedup by `Path.resolve()`. If the result is
   empty, fail-fast (R-DISC-010). Sort alphabetically by `filespec` for
   deterministic ordering (R-DISC-020).

   - **R-DISC-010** If the union of all glob patterns matches zero files
     under `--bundle-root`, the run exits with code 1 and a CliError-grade
     message that lists every pattern that was tried. This is a user
     error, not fail-slow eligible.
   - **R-DISC-020** Discovered files are sorted by `filespec` (i.e., by
     their path relative to `--bundle-root`, with forward slashes,
     ascending lexical order). Sort precedes any per-label work so that
     scrape order, row order, and progress-bar order all match.
5. **Scrape each label** in order:
   1. Reject UTF-8 BOM up front (R-PARSE-001).
   2. Parse with `lxml.etree.parse(str(path))`.
   3. Extract `xsi:schemaLocation` URLs; download/cache XSDs (§11);
      cross-check that within this run, every namespace URI maps to a single
      schema URL/version (R-SCH-040).
   4. Validate `<logical_identifier>` against the LID regex (R-LID-001).
      Require `<version_id>` (R-LID-010). Insert this label's LID into
      a per-run "seen LIDs" map; if the same LID was already seen,
      raise the cross-label uniqueness error per R-LID-020 (caught at
      the per-label boundary under `--fail-slow`).
   5. Build per-label dict of `{canonical_xpath → text_value}` by walking the
      tree (§9–§10). Apply `xsi:nil="true"` substitution (§12).
   6. Compute auto-columns (§8) for this label.
6. **Filter / project columns**. Restrict each per-label dict to the
   selectors named in the config's `columns:` list: XPath columns keep
   the entry whose canonical form matches exactly (R-MAP-310), auto-columns
   are computed per §8. Drop unselected XPaths silently. Order the output
   columns exactly as declared in the `columns:` list (R-MAP-320). The
   empty-column-set case is rejected earlier at config validation time
   (R-MAP-312).
7. **Sort rows** alphabetically by `filespec` by default; if `output.sort_by` is
   set in the merged config, use that (R-SORT-010..R-SORT-030).
8. **Per-column quoting analysis** (R-CSV-040..R-CSV-050).
9. **Write CSV** in variable-width or fixed-width mode (§13).
10. **Generate label** via PdsTemplate (§14).
11. **Exit 0**.

### 4.2 Determinism

- **R-IDX-001** For a fixed set of inputs (bundle, patterns, config, mapping,
  schemas), every run produces byte-identical CSV and label files (modulo any
  PdsTemplate macro outputs that depend on wall-clock time, which the template
  may include via `$DATETIME(...)$` etc.).
- **R-IDX-002** Discovery order, column order, row order, and field-width
  computations are independent of OS file-system iteration order.

## 5. Subcommand semantics — `generate_xpath_list`

### 5.1 Pipeline

1. Parse CLI args (§3.4).
2. Load the config chain (§15). Column resolution (§4.1 step 3) is
   SKIPPED — this subcommand derives its output from the discovered
   XPaths themselves and needs no `columns:` list.
3. Discover label files (§4.1 step 4, including R-DISC-010 and
   R-DISC-020).
4. Scrape each label (§4.1 step 5 sub-steps 1–5). Auto-column
   computation (§4.1 step 5 sub-step 6) is SKIPPED.
5. Aggregate the union of all canonical XPaths discovered across all
   labels, preserving the order of first appearance across the
   alphabetically-sorted `filespec` order (R-XPL-010).
6. Write the resulting XPaths to the output file as a paste-ready YAML
   `columns:` block, one entry per first-occurrence XPath, with `name:`
   defaulted to the XPath text for the user to edit (R-XPL-020). The
   file is UTF-8 with LF line endings. The default output file is
   `./columns.yaml` (auto-numbered `columns_1.yaml`, … when present); a
   user-supplied `--output-file` without an extension gets `.yaml`
   appended, and any explicit extension is honored. No PDS4 label is
   generated. The "filter / project columns", "sort rows", "per-column
   quoting analysis", "write CSV", and "generate label" steps of §4.1
   (steps 6–10) do not apply.
7. Exit 0.

### 5.2 Output format

- **R-XPL-001** `generate_xpath_list` reads no `columns:` list and no
  external selection file; its output is derived solely from the XPaths
  discovered in the labels.
- **R-XPL-002** The XPaths emitted are in the canonical form defined in §10 and
  are suitable for direct use as `xpath:` selectors in a config `columns:`
  block.

## 6. Subcommand semantics — `copy_default_config`

### 6.1 Pipeline

1. Load the packaged default config YAML via
   `importlib.resources.files('pds4indextools.templates') / 'default_config.yaml'`.
2. Read its bytes (R-CFG-201).
3. If `--output-file` exists and `--force` is not set, fail-fast with exit code 1
   (R-CLI-031).
4. Write the bytes verbatim to `--output-file`. No reformatting; no PdsTemplate
   substitution; the YAML is byte-identical to the packaged source.
5. Exit 0.

### 6.2 Notes

- **R-CFG-201** The packaged file is the canonical reference. If it is updated,
  this subcommand reflects the change without requiring code edits.

## 7. Column selection (`columns:` config)

Output columns are declared in the merged config's `columns:` list
(there is no separate mapping-file format). Each list entry is a
`ColumnSpec` model (defined in `pds4indextools/config.py`):

```python
class ColumnSpec(BaseModel):
    model_config = {"extra": "forbid"}  # future per-column keys added deliberately
    xpath: str | None = None   # canonical XPath selector
    auto:  str | None = None   # one of the five auto-column tokens (R-AUTO-001)
    name:  str | None = None   # emitted header; None/blank -> selector text
```

### 7.1 Entry shape

- **R-MAP-300** Exactly one of `xpath` / `auto` is set per entry (a
  validation error names the offending entry's zero-based index). An
  `xpath` selector is matched against a label's canonical XPaths by
  exact string equality — no globbing, wildcarding, or pattern
  matching; it must match exactly the form produced by §10. An `auto`
  selector MUST be one of the five auto-column tokens (R-AUTO-001); any
  other token is a hard error whose message names the bad token and
  lists the five valid tokens.
- The emitted header is `name.strip()` when non-blank, else the raw
  selector text verbatim (the omitted-rename case: an XPath or auto
  token used as its own header).
- An `xpath` value MUST NOT contain internal whitespace.

### 7.2 Validation

- **R-MAP-030** Two entries with the same selector (two identical
  `xpath` values, or two identical `auto` tokens) are a hard
  `ConfigError` citing both entry indexes.
- **R-MAP-031** Two entries that resolve to the same emitted header are
  a hard `ConfigError` citing both entry indexes. The check is over the
  post-rename headers, with the selector itself acting as the implicit
  header when `name` is omitted.
- **R-MAP-043** A `name` MUST consist of ASCII printable characters in
  the range 0x20–0x7E only, MUST NOT contain a comma or a double-quote
  (`"`), and MUST be non-empty after strip. An omitted/blank `name`
  falls back to the raw selector as the header.

### 7.3 Application during scrape

- **R-MAP-310** Per label, after scrape and renumbering, every XPath
  whose canonical form is NOT named by an `xpath` entry is silently
  dropped from the row dict.
- **R-MAP-311** An `xpath` entry that never matches any XPath in any
  scraped label produces a column whose value is empty for every row.
  This is not a warning; the run succeeds.
- **R-MAP-312** A merged config whose `columns` list is empty (`[]`) is
  rejected at config-validation time with a `ConfigError` and exit code
  1 (NOT fail-slow eligible: this is a user/configuration error, not
  label-content). A merged config with NO `columns` key is likewise a
  `ConfigError` for `generate_index_file` (there is no all-columns
  fallback).
- **R-MAP-320** Output column order is exactly the declaration order of
  the `columns` list. Auto-column entries and XPath entries interleave
  freely.

### 7.4 Errors and exit codes

Column-configuration errors are user errors, not label-content errors.
They raise `ConfigError` and exit with code 1 (NOT eligible for
`--fail-slow`, because the column configuration is independent of label
content). The `columns` list is replaced wholesale by a later
`--config-file` in the chain (like every list, per R-CFG-050).

## 8. Auto-columns

### 8.1 Recognized tokens

- **R-AUTO-001** Exactly five auto-column tokens are recognized:
  `lid`, `lidvid`, `filespec`, `filename`, `bundle_name`. Any other
  value in a column entry's `auto` field is a hard error (§7.1).

### 8.2 Derivations

For a given label file with absolute path `P` parsed into tree `T`:

| Token | Value | Data type written into the index label |
|---|---|---|
| `lid` | The text of the unique `<logical_identifier>` element under `<Identification_Area>`, after `.strip()`. Presence and validity guaranteed by R-LID-001 before this column is computed. | `pds:ASCII_LID` |
| `lidvid` | `<lid>` + `'::'` + the text of the unique `<version_id>` element under `<Identification_Area>`, after `.strip()`. Presence guaranteed by R-LID-010. | `pds:ASCII_LIDVID_LID` |
| `filespec` | `Path(P).relative_to(bundle_root).as_posix()` (forward slashes always); MUST be ≤ 255 bytes (R-FS-010) | `pds:ASCII_File_Specification_Name` |
| `filename` | `Path(P).name` | `pds:ASCII_File_Name` |
| `bundle_name` | The 4th colon-separated token of `<lid>` (zero-indexed token 3); e.g. for `urn:nasa:pds:bundle_x:doc:thing` it is `bundle_x`. Always extractable when R-LID-001 passes. | `pds:ASCII_Text_Preserved` |

> The element lookups above use a namespace map that aliases the PDS4
> default namespace to the prefix `pds:`. The pseudo-XPaths here are
> intentionally informal; the implementation in `scraper.py` performs
> the lookups with explicit `lxml.etree` calls and raises the
> appropriate `LidError` if R-LID-001 / R-LID-010 fail before the
> `.strip()` is reached.

### 8.3 Validation

- **R-LID-001** Every label MUST contain exactly one
  `<logical_identifier>` element inside its `<Identification_Area>`.
  Its text value, after `.strip()`, MUST match the regex
  `^urn:[a-z0-9-]+:[a-z0-9-]+(?::[a-zA-Z0-9_.-]+){1,4}$` (the `urn_pds`
  pattern from PDS4 Standards Reference §6D.1). The first three
  tokens (`urn`, NID, NSS) are lowercase; the trailing 1–4 tokens may
  mix case. The full LID therefore has 4–7 colon-separated tokens,
  with `urn:nasa:pds:bundle` as the legal minimum. A missing or
  duplicated `<logical_identifier>`, or one whose text fails the regex,
  is a label-content error (fail-slow eligible). Because the regex
  guarantees ≥ 4 tokens, the `bundle_name` auto-column extraction
  (§8.2) is always defined when R-LID-001 passes; no separate
  validation is required.
- **R-LID-010** Every label MUST contain exactly one `<version_id>`
  element inside its `<Identification_Area>`, regardless of whether
  `lidvid` is requested. A missing or duplicated `<version_id>` is a
  label-content error (fail-slow eligible).
- **R-LID-020** Across all scraped labels in a single run, every
  `<logical_identifier>` value MUST be unique. If two or more labels
  share the same LID, the second-and-subsequent occurrences are a
  label-content error (fail-slow eligible) citing the offending LID
  value and the file paths of all colliding labels. The check uses
  the post-`.strip()` LID text, not LIDVID. (User decision: Round 7
  "duplicate_lid: error".)
- **R-FS-010** A `filespec` exceeding 255 bytes is a hard label-content error
  (fail-slow eligible).

### 8.4 Renaming auto-columns

- **R-AUTO-010** An auto-column entry may omit `name` (the token itself
  becomes the column header) or supply `name` (the supplied header is
  used). Either way, the data type recorded in the generated label is
  the type listed in the table in §8.2.

## 9. Label scraping

### 9.1 Parsing

- **R-PARSE-001** A label file beginning with a UTF-8 BOM (bytes
  `EF BB BF`) is rejected as a label-content error (fail-slow eligible).
- **R-PARSE-002** XML parsing is performed with
  `lxml.etree.parse(str(path))` (no resolver overrides, no DTD loading).
  An `lxml.etree.XMLSyntaxError` is caught and re-raised as `ParseError`
  (a `LabelError` subclass) using `raise ... from`, and treated as a
  label-content error (fail-slow eligible).
- **R-PARSE-003** The full DOM is held in memory for the duration of one
  label's scrape. There is no streaming pass over very large labels; if
  memory pressure ever becomes an issue, see Future Issue F7.
- **R-PARSE-010** For each label, the root element's tag is recorded but is
  not validated against any allowlist of PDS4 product classes. Any root tag
  is processed as the first segment of the canonical XPath.

### 9.2 Tree walk

- **R-SCRAPE-010** The tool performs a full pre-order traversal of the DOM,
  visiting every element exactly once. Column projection is applied
  AFTER renumbering (R-MAP-310), not during the walk, because
  renumbering requires complete knowledge of sibling occurrences.
- **R-SCRAPE-020** For each element with non-empty stripped text content,
  the value `' '.join(element.text.strip().split())` is stored under the
  canonical XPath of the element (whitespace collapse; see R-VAL-010).
- **R-SCRAPE-030** Elements with children are NOT stored at the parent
  level (only leaf-level text becomes a value). This matches legacy
  behavior.
- **R-SCRAPE-040** Attributes (e.g. `unit`) are NOT scraped. Only element
  text content participates in the index.

### 9.3 Whitespace and value normalization

- **R-VAL-010** Each scraped text value is normalized by stripping
  leading/trailing whitespace and collapsing every run of internal
  whitespace (including tabs and newlines) to a single ASCII space. This
  may strip semantic whitespace; see Future Issue F3.
- **R-VAL-020** If, after normalization, a value contains any ASCII
  control character (codepoints 0x00–0x1F or 0x7F) other than space
  (0x20), the run fails fast (label-content error, fail-slow eligible).
- **R-VAL-030** If, after normalization, a value contains any non-ASCII
  byte (codepoint ≥ 0x80), the run fails fast (label-content error,
  fail-slow eligible). See Future Issue F2.
- **R-VAL-040** If, after normalization, a value contains a literal `"`
  (double-quote) character, the placeholder behavior pending Future
  Issue F1 is mode-specific:
  - In variable-width mode: a hard label-content error
    (`ScrapedValueError`, fail-slow eligible). Embedding `"` inside a
    quoted CSV field would require RFC 4180 doubling, which is not yet
    decided.
  - In fixed-width mode: the `"` byte is passed through unchanged into
    the cell. (Legacy behavior; quoted columns remain rare in
    fixed-width pipelines.)
  This rule is deliberately mode-dependent only as a placeholder; the
  final, mode-independent policy is tracked under F1.

## 10. XPath canonicalization

The output of step 9.2 is an in-memory dict keyed by the lxml-native XPath
form (e.g. `/{http://pds.nasa.gov/pds4/pds/v1}Product_Observational/...`).
Before further processing, every key is rewritten to a canonical form
suitable for comparison against the config's `columns:` selectors and
for emission as a header.

### 10.1 Canonical form

The canonical form has the shape:

```text
ns0:Tag<n0>/ns1:Tag<n1>/.../nsK:Tag<nK>
```

where:

- **R-XP-001** Every segment carries a namespace prefix followed by a
  colon. The default namespace (no prefix) is aliased to `pds:` always
  (R-XP-010).
- **R-XP-002** Every segment carries an angle-bracketed integer occurrence
  predicate `<n>`, even when `n == 1`. There are no implicit `<1>`s.
- **R-XP-003** Path separator is forward slash `/`. There is no leading
  slash.

### 10.2 Namespace aliasing

- **R-XP-010** The XML default namespace (the one with key `None` in
  `root.nsmap`) is always aliased to `pds:` in canonical XPaths.
- **R-XP-011** All other namespace prefixes declared on the root element
  are preserved verbatim. If two distinct namespace URIs collide on the
  same prefix between two labels, R-SCH-040 catches the inconsistency.
- **R-XP-012** The `xmlns:xsi` namespace is treated as any other and is
  available on attributes (which are not scraped) but does not appear on
  element XPaths.
- **R-XP-013** A label whose root element declares NO default namespace
  (i.e. `root.nsmap.get(None) is None`) is a label-content error
  (`ParseError`, fail-slow eligible). All PDS4 labels are required to
  declare the PDS4 default namespace.

### 10.3 Renumbering

lxml's `tree.getpath()` produces predicates like `[2]` based on the
element's STRUCTURAL position among sibling tags. We rewrite these to
OCCURRENCE-based predicates `<n>` where `n` is the 1-based index among
elements that share both the same tag and the same parent path segment.

- **R-XP-020** Renumbering is performed per-label, after the full tree
  walk, on the keys of the per-label dict. The algorithm groups XPaths by
  prefix (same parent, same tag), enumerates the distinct numeric indexes
  in ascending order, and remaps them to a dense sequence starting at 1.
  See `legacy/pds4indextools/pds4_create_xml_index.py::renumber_xpaths`
  for the reference implementation; the new implementation reproduces the
  same output for the same input.
- **R-XP-021** When multiple distinct `[n]` predicates from lxml map to
  the same canonical `<m>` (because tags interleave non-contiguously),
  the algorithm raises a label-content error citing the offending XPath
  pattern. (This is the "non-monotone interleave" case noted in the
  legacy docstring.)
- **R-XP-030** Renumbering preserves order of first occurrence within the
  per-label dict.

## 11. XML schema type lookup

Every column emitted in the index file (whether a mapped XPath or an
auto-column) requires a PDS4 data type to be written into the index label.

### 11.1 Auto-column types

Listed in §8.2. These are hard-coded; they do NOT depend on schema lookup.

### 11.2 Scraped XPath types

For each canonical XPath, the leaf tag (the last `/` segment, after stripping
the predicate, e.g. `pds:logical_identifier`) is resolved to a PDS4 base
type by:

- **R-SCH-010** Downloading every URL listed in the label's
  `xsi:schemaLocation` attribute that ends in `.xsd`. Downloads use
  `requests.get(url)` with a 30-second timeout. The body is parsed with
  `lxml.etree.fromstring`.
- **R-SCH-020** Downloads are cached on disk forever. The cache directory
  is `xsd_cache_dir` from the merged config if set (must be absolute);
  otherwise `platformdirs.user_cache_dir('pds4indextools')`. The cache
  filename for a URL is `sha256(url).hexdigest()` plus the original
  `.xsd` extension. Cache misses cause a download; the cache is appended
  to but never invalidated by the tool itself.
- **R-SCH-030** Type resolution applies the chain of XPath queries used by
  the legacy implementation (see `legacy::find_base_attribute`), trying
  the bare leaf tag first and then `<tag>_WO_Units` as a fallback for
  unit-aware elements. The first non-None match wins.
- **R-SCH-040** Across all labels in a single run, every namespace URI must
  resolve to exactly ONE schema URL (and therefore one schema version).
  The first label to declare a given namespace fixes its schema URL; any
  subsequent label that declares the same namespace pointing to a
  different URL is a label-content error (fail-slow eligible).
- **R-SCH-050** If type resolution fails to produce a base type for an
  emitted XPath, the run fails fast (label-content error, fail-slow
  eligible). Empty (all-null) columns whose type can NOT be resolved are
  also failures; we do NOT silently substitute a default type.
- **R-SCH-060** If a downloaded XSD is unreachable (network error,
  connection refused, HTTP non-2xx), the run halts with exit code 2. This
  is environmental, not label-content; `--fail-slow` does NOT mask it.
- **R-SCH-070** If an on-disk cache file is corrupted (cannot be parsed as
  XML), the run halts with exit code 2. Cache corruption is environmental
  and not auto-repaired (users delete the cache file manually).

### 11.3 Type values

The base type is recorded with its full namespace prefix as it appears in
the XSD (e.g. `pds:ASCII_Date_YMD`). When written into the generated
label's `<Field_Delimited>/<data_type>` element, the namespace prefix is
stripped (legacy behavior; the schema enclosing scope makes it
unambiguous).

## 12. Nil and missing-value handling

There are two distinct cases:

| Case | Meaning | Substitution |
|---|---|---|
| Nilled element | A label HAS the element with attribute `xsi:nil="true"`. | Use the config-supplied default for `(data_type, nilReason)`. |
| Missing element (in mapping but absent from label) | The label simply does not contain the requested XPath. | Emit empty string. |

### 12.1 Nilled elements

- **R-NIL-001** A nilled element is detected ONLY by the presence of the
  attribute `xsi:nil="true"`. Empty text content WITHOUT `xsi:nil="true"` is
  NOT treated as nil; it is treated as an empty value (which then triggers
  R-NIL-040 below).
- **R-NIL-010** The nilled element MUST also have a `nilReason` attribute
  whose value is one of `inapplicable`, `missing`, `unknown`, `anticipated`.
  Any other value (or a missing `nilReason`) is a label-content error
  (fail-slow eligible).
- **R-NIL-020** The element's data type is resolved per §11. The default
  value substituted is `config.nillable[<data_type>][<nilReason>]`.
- **R-NIL-030** If the data type is not present in `config.nillable` (after
  config chain merge), the run fails (label-content error, fail-slow
  eligible). Users add types to their custom config.
- **R-NIL-040** A leaf element with empty/whitespace-only text and no
  children, AND no `xsi:nil="true"` attribute, is treated as if the
  element did not appear in the label (its XPath is not added to the row
  dict). The corresponding cell is therefore the empty string per
  R-MISS-010.

### 12.2 Missing elements (no XPath in this label)

- **R-MISS-010** When a config `columns:` entry names an XPath that is not
  present in a given label, the cell value is the empty string. No nillable
  substitution occurs.
- **R-MISS-020** This applies whether or not the XPath is present in OTHER
  labels in the same run.

## 13. CSV output format

### 13.1 General CSV rules

- **R-CSV-001** The CSV file is written using `csv.writer` from the stdlib.
  No third-party library (no pandas) is used.
- **R-CSV-002** Encoding is UTF-8 without BOM. Because R-VAL-030 forbids
  non-ASCII content, the bytes are also valid US-ASCII.
- **R-CSV-003** Line terminator is taken from `output.line_ending` in the
  merged config:
  - `'LF'` → `b'\n'`
  - `'CRLF'` → `b'\r\n'`
  - default is `'LF'`.
  This value MUST be consistent with the `<record_delimiter>` element
  written into the generated label (R-LBL-060). The corresponding
  PdsTemplate record-delimiter mode is invoked rather than constructing
  the value manually.
- **R-CSV-004** Field delimiter is always comma (`,`); not configurable.
- **R-CSV-005** No trailing comma is written after the last column on
  any row, in either variable-width or fixed-width mode.

### 13.2 Header row

- **R-CSV-010** Exactly one header row is written, before any data row.
- **R-CSV-011** Header values are the emitted headers of the config
  `columns:` entries (each entry's `name`, or its raw selector text when
  `name` is omitted, per §7).
- **R-CSV-012** Headers are emitted unquoted in BOTH variable-width and
  fixed-width modes. (Per Round 6 user choice: header is not padded in
  fixed-width mode either.)

### 13.3 Data rows

- **R-CSV-020** One data row per scraped label, in the order chosen per
  R-SORT-010..R-SORT-030.
- **R-CSV-021** Field order matches header order.

### 13.4 Per-column quoting analysis

- **R-CSV-040** Before writing, the tool builds the full in-memory row
  list and computes per-column statistics: max byte length AND a
  `must_quote` boolean (true iff any value in the column contains a
  comma).
- **R-CSV-050** If `must_quote[c]` is true, every DATA cell in column
  `c` is wrapped in `"..."` quotes. Header cells are never quoted
  regardless of `must_quote[c]` (R-CSV-012). Each quoted cell's
  contribution to the column-width computation includes the two quote
  bytes.
- **R-CSV-051** If a column's `must_quote` is false, no cell in that
  column is quoted (header or data).
- **R-CSV-052** Header cell contents do not participate in the
  `must_quote[c]` computation; only data values do.

### 13.5 Variable-width mode

- **R-CSV-060** When `output.fixed_width` is false (the default), data
  rows contain each cell's value (with column-wide quoting per R-CSV-050)
  followed by a comma except after the last column, then the line
  terminator.
- **R-CSV-061** No padding is applied. Column widths are computed only
  for the purpose of writing `<maximum_field_length>` into the index
  label.

### 13.6 Fixed-width mode

- **R-CSV-070** When `output.fixed_width` is true, every data cell is
  right-padded with ASCII space (`0x20`) to a column width equal to the
  max byte length of any value in that column (where the max length
  includes the two surrounding quote bytes when `must_quote[c]` is true).
- **R-CSV-071** Headers are NOT padded in fixed-width mode (per Round 6
  decision). The header row is written exactly like a variable-width
  header. Column boundaries in the header therefore differ from those in
  data rows; both remain CSV-parseable because commas separate columns.
- **R-CSV-072** Fixed-width data rows DO NOT have a trailing comma after
  the last column (R-CSV-005).
- **R-CSV-073** All-empty columns receive `field_length = 0` and write
  zero-byte values; the row layout is `value0,,value2` etc. with two
  consecutive commas. This is a legal CSV row.

### 13.7 Byte-length policy

- **R-CSV-080** Field-length values written into the index label are
  byte lengths. Because R-VAL-030 forbids non-ASCII bytes, byte length
  equals character length.

### 13.8 Sort

- **R-SORT-010** An unset or empty `sort_by` performs NO re-sort — rows
  keep discovery order, which is already `filespec`-sorted per R-DISC-020.
- **R-SORT-020** If `output.sort_by` is a non-empty list, rows are
  sorted using a stable Python `sorted()` keyed by the listed columns in
  order. A leading `-` on a column name means descending. Each column
  listed MUST exist in the final emitted column set; otherwise a hard
  error (NOT eligible for `--fail-slow` because it is a config error).
- **R-SORT-030** Sort comparisons are string comparisons on the cell's
  value AS WRITTEN to the CSV (after normalization, before quoting/padding).

## 14. Index label generation

### 14.1 Template

- **R-LBL-001** When `--label-template` is omitted, the tool uses the
  packaged template at `pds4indextools/templates/index_label_template.xml`,
  loaded via `importlib.resources`.
- **R-LBL-002** When `--label-template PATH` is supplied, that file is
  used instead. The path is resolved relative to cwd (or absolute).
- **R-LBL-003** No validation is performed on the user-supplied template
  beyond what PdsTemplate itself does at parse time. Missing variable
  references at substitution time bubble up as `OutputError` (exit 2).

### 14.2 PdsTemplate variable contract

The tool builds the substitution dict by:

1. Starting with the merged `config.label_contents` (verbatim passthrough,
   including any user-added keys allowed by `extra='allow'`).
2. Overlaying the BASE variables in the table below, computed by the
   tool. The "Override?" column says whether a same-named key in
   `config.label_contents` is allowed to win:
   - **Override = no** (reserved): the tool's value always wins; if
     the user attempts to set the same key in `label_contents`,
     `ConfigError` is raised at validation time naming the offending
     key.
   - **Override = yes**: the user's value (if any) wins; the table
     entry then describes the default the tool supplies when the user
     omits the key.

| Variable | Origin | Override? | Notes |
|---|---|---|---|
| `index_file_name` | Absolute path of the just-written CSV | no | Used by `$BASENAME(...)$`, `$FILE_MD5(...)$`, etc. |
| `Field_Content` | List of dicts, one per output column | no | See §14.3 |
| `fields` | `len(Field_Content)` (column count) | no | Used by `<fields>` in `<Table_*>` |
| `records` | Number of data rows written to the CSV (= number of successfully scraped labels). Equals the discovered-label count, since fail-slow either succeeds completely or aborts before writing | no | Used by `<records>` in `<Table_*>` |
| `Table_Character` | `True` iff `output.fixed_width` is true | no |  |
| `Table_Delimited` | `True` iff `output.fixed_width` is false | no |  |
| `Product_Ancillary` | Derived from `label_contents.product_class` (R-LBL-010) | no |  |
| `Product_Metadata_Supplemental` | Derived from `label_contents.product_class` (R-LBL-010) | no |  |
| `object_length_h` | Byte length of the header row, including line terminator | no |  |
| `object_length_t` | Byte length of the entire CSV file on disk | no |  |
| `maximum_record_length` | Byte length of the longest row, including line terminator (variable-width); record_length without terminator (fixed-width) | no |  |

Creation date/time and MD5 checksum are NOT supplied by the tool as
substitution variables: the packaged template uses PdsTemplate macros
(`$CURRENT_ZULU()$`, `$FILE_ZULU(index_file_name)$`,
`$FILE_MD5(index_file_name)$`) directly. This is per Round 7 ("look at
PdsTemplate documentation; do not duplicate effort").

- **R-LBL-010** The tool derives the two product-class booleans from
  `config.label_contents.product_class`:
  - `'Product_Ancillary'` → `Product_Ancillary=True`, `Product_Metadata_Supplemental=False`
  - `'Product_Metadata_Supplemental'` → reverse
  - any other value is a config error.
- **R-LBL-011** `product_class` is a required field in the merged config.
- **R-LBL-012** Every BASE variable in the §14.2 table marked
  "Override = no" is reserved. If the merged `label_contents` (or any
  pass-through key inherited via `extra='allow'`) contains a key whose
  name matches one of these reserved names, validation fails with
  `ConfigError` (exit 1), naming the offending key. The reserved
  names are: `index_file_name`, `Field_Content`, `fields`, `records`,
  `Table_Character`, `Table_Delimited`, `Product_Ancillary`,
  `Product_Metadata_Supplemental`, `object_length_h`,
  `object_length_t`, `maximum_record_length`.

### 14.3 `Field_Content` shape

- **R-LBL-020** Each entry of the `Field_Content` list passed to
  PdsTemplate is a dict with EXACTLY the following seven keys:

  - `name` — the column header as it appears in the CSV (the short name
    from the mapping, or the auto-column rename, or the raw canonical
    XPath when there was no mapping).
  - `field_number` — 1-based integer (column index + 1).
  - `field_location` — 1-based byte offset of this column from the start
    of a fixed-width data row (only meaningful when `Table_Character`
    is true, but always supplied; for `Table_Delimited` it equals the
    1-based comma-counted column position).
  - `data_type` — the resolved PDS4 base type without namespace prefix
    (e.g. `ASCII_LID`, `ASCII_Short_String_Collapsed`).
  - `field_length` — fixed-width column width in bytes (used only by
    `Table_Character`).
  - `maximum_field_length` — variable-width max column width in bytes
    (used only by `Table_Delimited`).
  - `xpath` — the original raw canonical XPath (or the auto-column
    token); available for templates that wish to embed traceability
    info in `<description>`.

### 14.4 PdsTemplate invocation

- **R-LBL-040** The tool calls `pdstemplate.PdsTemplate(template_path)`
  followed by `template.write(substitution_dict, output_label_path)`.
  No additional macros or preprocess steps are added by the tool.
- **R-LBL-050** Output label path is `<csv_stem>.lblx` next to the CSV.

### 14.5 Record delimiter consistency

- **R-LBL-060** The tool MUST configure PdsTemplate's record-delimiter
  mode (per its API) so that the `<record_delimiter>` element in the
  emitted label matches the actual byte sequence used to terminate CSV
  records (R-CSV-003). Specifically, `'LF'` → `<record_delimiter>Line-Feed</record_delimiter>`,
  `'CRLF'` → `<record_delimiter>Carriage-Return Line-Feed</record_delimiter>`.

### 14.6 MD5 and creation date

- **R-LBL-070** The MD5 checksum of the CSV is computed by PdsTemplate's
  `$FILE_MD5(index_file_name)$` macro inside the template. The tool does
  not compute the checksum in Python.
- **R-LBL-080** Creation timestamps are computed by PdsTemplate macros
  (`$CURRENT_ZULU()$`, `$FILE_ZULU(...)$`, `$DATETIME(...)$`) inside the
  template. The tool does not pre-compute or pass any creation-date
  variable; templates that need a creation date MUST invoke a
  PdsTemplate macro themselves.

### 14.7 Modification history

- **R-LBL-090** `Modification_Detail` (or `Modification_History`) data,
  when supplied in `config.label_contents`, is passed through. When the
  user supplies NO `Modification_Detail`, the tool GENERATES a default
  single-entry modification history (rather than emitting an empty one)
  so the generated label always carries a valid `Modification_History`.
- **R-LBL-091** Normalization of `Modification_Detail` before passthrough
  to PdsTemplate:
  - A single dict is wrapped into a one-element list.
  - A list is passed through unchanged (in declared order).
  - `None` (or absent) becomes a default single-entry list (one
    generated `Modification_Detail`), never an empty list.

## 15. Configuration file

### 15.1 Loading

- **R-CFG-010** Config files are loaded with `yaml.safe_load`. No PyYAML
  custom tags or constructors are registered.
- **R-CFG-011** Each loaded YAML must be a mapping at the top level (not
  a list, scalar, or null). Otherwise the run fails with
  `ConfigError` and exit code 1.

### 15.2 Pydantic schema

The merged config is validated with pydantic v2 models. Approximate Python
shapes (full implementation lives in `pds4indextools/config.py`):

```python
class NillableEntry(BaseModel):
    model_config = {"extra": "forbid"}
    inapplicable: str | int | float
    missing:      str | int | float
    unknown:      str | int | float
    anticipated:  str | int | float

class OutputSection(BaseModel):
    model_config = {"extra": "forbid"}
    fixed_width:  bool                = False
    sort_by:      list[str]           = []
    line_ending:  Literal["LF","CRLF"] = "LF"

class CitationInformation(BaseModel):
    model_config = {"extra": "allow"}
    author_list:       str | list[str] | None = None
    editor_list:       str | None             = None
    publication_year:  int | str | None       = None
    doi:               str | None             = None
    keyword:           str | list[str] | None = None
    description:       str | None             = None
    Funding_Acknowledgement: dict | None      = None

class ModificationDetail(BaseModel):
    model_config = {"extra": "allow"}
    modification_date: str
    version_id:        str
    description:       str

class LabelContents(BaseModel):
    model_config = {"extra": "allow"}            # passthrough to PdsTemplate
    logical_identifier: str                      # REQUIRED in user config
    product_class:      Literal["Product_Ancillary",
                                "Product_Metadata_Supplemental"]
    version_id:         str | None      = None
    title:              str | None      = None
    Citation_Information: CitationInformation | None = None
    Modification_Detail:  list[ModificationDetail] | ModificationDetail | None = None
    Internal_Reference:   list[dict] | None = None
    External_Reference:   list[dict] | None = None
    Source_Product_Internal: list[dict] | None = None
    Source_Product_External: list[dict] | None = None
    File_Area_Ancillary:  dict | None = None
    File_Area_Metadata:   dict | None = None

class IndexConfig(BaseModel):
    model_config = {"extra": "forbid"}
    nillable:        dict[str, NillableEntry] = {}   # extra='allow' on the keys
    label_contents:  LabelContents
    output:          OutputSection           = OutputSection()
    columns:         list[ColumnSpec] | None = None  # column selection, §7
    xsd_cache_dir:   AbsolutePath | None     = None
```

> `ColumnSpec` is defined in §7. `columns` is optional at load time
> (`generate_xpath_list` and `copy_default_config` need no columns);
> `generate_index_file` requires a non-empty list (R-MAP-312).

> `AbsolutePath` above is shorthand for `Annotated[Path,
> AfterValidator(_require_absolute)]` defined in
> `pds4indextools/config.py`. The validator raises `ValueError` if the
> path is not absolute (per R-CFG-040); pydantic converts that into a
> `ValidationError`.

- **R-CFG-020** The TOP-LEVEL config has `extra='forbid'`: only the five
  keys above are accepted. Any other top-level key is a hard error.
- **R-CFG-021** `OutputSection` has `extra='forbid'`.
- **R-CFG-022** `LabelContents` has `extra='allow'`. Unknown keys are
  silently passed through to PdsTemplate as substitution variables.
- **R-CFG-023** Each entry inside `nillable` (the per-data-type dict) has
  `extra='forbid'` (only the four nilReason values), but the dict KEYS
  (data type names) are unconstrained.
- **R-CFG-024** `xsd_cache_dir`, when set, MUST be absolute (R-CFG-040).

### 15.3 Required fields in user-supplied configs

The system default supplies sensible values for `nillable`, `output`, and
`xsd_cache_dir` (the last is `null`, meaning use platformdirs). The user's
config(s) MUST collectively supply at minimum:

- **R-CFG-030** `label_contents.logical_identifier` (the LID for the
  GENERATED index label).
- **R-CFG-031** `label_contents.product_class`.

If those are missing after merge, validation fails with a clear error
naming the missing fields.

### 15.4 Path resolution inside config

- **R-CFG-040** Any path-valued field inside a config file MUST be
  absolute. Relative paths are NOT resolved (relative to anything) and
  raise a config error with the offending field name.

### 15.5 Merge / overlay semantics

- **R-CFG-050** Configs are deep-merged: dicts are merged recursively;
  lists and scalars are replaced (not concatenated).
- **R-CFG-051** Order is `system_default` → first `--config-file` → second
  `--config-file` → ...; later values override earlier values.
- **R-CFG-052** Validation (R-CFG-020..R-CFG-024) is applied AFTER the
  full merge, so each individual user file may be partial.

### 15.6 System default contents

The system default lives at
`src/pds4indextools/templates/default_config.yaml`. It includes:

- The six `nillable` entries from the legacy `default_config.yaml`
  (`pds:ASCII_Date_YMD`, `pds:ASCII_Date_Time_YMD`,
  `pds:ASCII_Date_Time_YMD_UTC`, `pds:ASCII_Integer`, `pds:ASCII_Real`,
  `pds:ASCII_Short_String_Collapsed`).
- An `output` section with `fixed_width: false`, `sort_by: []`,
  `line_ending: LF`.
- `xsd_cache_dir: null`.
- NO `label_contents` section. Users MUST supply their own (since LID
  and product_class are not safely defaultable).

## 16. Path resolution and filesystem

- **R-FS-001** Every path supplied on the CLI (`--bundle-root`,
  `--label-template`, `--output-file`, the
  `copy_default_config` destination, every `--config-file`) is treated
  as absolute if it starts with the platform's path-anchor; otherwise
  it is resolved against the current working directory at startup.
- **R-FS-002** `--bundle-root` may be a symlink to a directory; the
  symlink is followed and the resolved real path is used internally.
- **R-FS-003** Glob expansion uses `pathlib.Path.glob(pattern)` which
  follows symlinks. The tool does NOT detect symlink loops; if the
  caller has cyclic links under their bundle, behavior is undefined
  (typically OS-level recursion limits halt the process).
- **R-FS-004** Discovered files are deduplicated by `Path.resolve()`
  (so the same file matched by two patterns appears once).
- **R-FS-005** Schema URLs are accepted with any URL scheme. `http://`
  and `https://` are fetched via `requests`; `file://` URLs are
  fetched via `requests-file` (registered as an adapter on the
  `requests` session). Other schemes (e.g. `ftp://`) are passed
  through to the same session and succeed iff the user has registered
  an additional adapter or the URL works via the standard requests
  adapter chain. `requests-file` is a runtime dependency (§21.1).

## 17. Error model and `--fail-slow`

### 17.1 Exception hierarchy

All custom exceptions live in `pds4indextools.errors`:

```text
Pds4IndexError                       (base; never instantiated directly)
├── CliError                         (argparse / user-input errors → exit 1)
├── ConfigError                      (config validation, columns, sort_by misuse → exit 1)
├── LabelError                       (label-content errors → exit 2)
│   ├── ParseError                   (XML parse, BOM, missing default ns)
│   ├── LidError                     (LID regex, missing version_id, cross-label LID collision per R-LID-020)
│   ├── XPathError                   (renumber non-monotone interleave)
│   ├── NilError                     (bad nilReason, unknown dtype)
│   └── ScrapedValueError            (non-ASCII, control chars, value contains `"`)
├── SchemaError                      (XSD-related → exit 2)
│   ├── SchemaResolutionError        (type not found in any XSD)
│   ├── SchemaVersionError           (cross-label namespace inconsistency)
│   ├── SchemaNetworkError           (download failure; NOT fail-slow eligible)
│   └── SchemaCacheError             (cache file unreadable; NOT fail-slow eligible)
├── OutputError                      (CSV/label write failures → exit 2)
└── FailSlowAggregateError           (programmatic-API only; raised when
                                      --fail-slow accumulated ≥1 errors,
                                      per R-API-004 / R-FSLOW-120 → exit 2)
```

> **Note:** The `LabelError` value-content subclass is named `ScrapedValueError`,
> NOT `ValueError`, to avoid shadowing the Python builtin
> (`python_best_practices.mdc` §1).

- **R-ERR-001** `LabelError` and most `SchemaError` subclasses (except
  `SchemaNetworkError` and `SchemaCacheError`) are FAIL-SLOW ELIGIBLE.
  All other errors halt immediately even under `--fail-slow`.
- **R-ERR-002** `KeyboardInterrupt` (SIGINT) is caught at the main entry
  point and converted into a clean stderr message `aborted by user` plus
  exit code 130. Both the CSV and the `.lblx` are written to temp paths
  within the same directory as their final targets; each is renamed
  atomically into place only after its full bytes have been flushed and
  closed. If SIGINT arrives before the CSV rename, the CSV temp file is
  unlinked and no label is generated. If SIGINT arrives between the CSV
  rename and the label rename, the CSV is left in place and the label
  temp file is unlinked. The tool never leaves a partially-written
  output file at the final path.

### 17.2 Exit codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | User / CLI error (`CliError`, `ConfigError`) |
| 2 | Runtime / data error (`LabelError`, `SchemaError`, `OutputError`, `FailSlowAggregateError`) |
| 3 | Internal / unhandled exception (any non-`Pds4IndexError` reaching the top level; the traceback is printed) |
| 130 | SIGINT |

### 17.3 `--fail-slow` semantics

- **R-FSLOW-100** `--fail-slow` is accepted by `generate_index_file` and
  `generate_xpath_list` only. (`copy_default_config` does no scraping.)
- **R-FSLOW-110** When `--fail-slow` is set, every fail-slow-eligible error
  raised during scraping (R-ERR-001), including cross-label errors such
  as `SchemaVersionError` (R-SCH-040), is caught at the per-label
  boundary, converted into a WARNING-level log message including the
  file path and a one-line cause, and appended to an in-memory list.
  Scraping continues with the next label.
- **R-FSLOW-120** After all labels have been processed (or attempted), if
  the accumulated warnings list is non-empty, the run does NOT proceed
  to CSV/label generation. The CLI prints a final summary block to
  stderr listing every accumulated message (each one re-emitted, so
  log filtering tools can consume them) and exits with code 2. The
  programmatic API (`run_*` functions) raises
  `FailSlowAggregateError` per R-API-004 instead of printing the
  summary; the caller is responsible for formatting it.
- **R-FSLOW-130** When the run completes scraping with an empty
  accumulated-warnings list, the pipeline proceeds to the normal
  write phase per §4.1 steps 7–11 (or §5.1 steps 5–7 for
  `generate_xpath_list`). The output is byte-identical to the same
  invocation without `--fail-slow`.
- **R-FSLOW-140** No warning-log file is written. All warnings are
  emitted to stderr via the standard logging facility.

## 18. Logging and progress

### 18.1 Logger setup

- **R-LOG-001** All log output is written to stderr.
- **R-LOG-002** Log records use the format `LEVEL [module] message`
  where `module` is the short logger name (e.g. `cli`, `scraper`,
  `label_writer`). No timestamps. No color.
- **R-LOG-003** The tool's logger is configured at the root of the
  `pds4indextools` namespace; library users who import the package
  inherit the existing root-logger configuration of their host process.
  Library code never calls `logging.basicConfig`; only the CLI entry
  point does.

| Flag | Level |
|---|---|
| (none) | WARNING |
| `-v` | INFO |
| `-vv` | DEBUG |
| `-vvv` | DEBUG (clamped; reserved for future TRACE-style output) |

- **R-LOG-010** The logger level is established before any subcommand

### 18.3 Progress

- **R-LOG-020** During label scraping, when stderr is a TTY, `tqdm` is

  ``disable=True`` and no progress bar is rendered. The verbosity flag

- **R-API-004** Programmatic-API error contract: any condition that
  the CLI maps to a non-zero exit code MUST surface as an exception
  raised from the `run_*` function, NOT as an "error" field on the
  result dataclass.
  - Exit 1 / 2 → the corresponding `Pds4IndexError` subclass is raised
    (`CliError`, `ConfigError`, `LabelError`, `SchemaError`, or
    `OutputError`).
  - `--fail-slow` accumulated-warnings abort (R-FSLOW-120) → raises
    `FailSlowAggregateError` (a `Pds4IndexError` subclass with an
    `errors: list[Pds4IndexError]` attribute holding each accumulated
    sub-error in the order they were caught).
  - Exit 0 → the result dataclass is returned. Its `warnings` field
    contains advisory messages only (e.g. R-OUT-013 overwrite
    notices), never fail-slow errors.
  - SIGINT (exit 130) propagates as `KeyboardInterrupt`; the `run_*`
    function still performs the temp-file cleanup of R-ERR-002 before
    re-raising.

## 22. Testing strategy

### 22.1 Approach

- **R-TST-001** Test-driven development per
  `python_best_practices.mdc` §7.1: tests are written before
  implementation; red → green → refactor.
- **R-TST-002** Two layers: per-module unit tests (in `tests/unit/`)
  invoking functions directly; integration tests (in
  `tests/integration/`) invoking `pds4indextools.main([...])`
  in-process.
- **R-TST-003** A small subprocess smoke suite
  (`tests/integration/test_subprocess_smoke.py`) invokes the installed
  console script via `subprocess.run([sys.executable, '-m',
  'pds4indextools', ...])` for one happy-path and one canonical failure
  per subcommand (R-CLI grammar verification end-to-end).

### 22.2 Coverage

- **R-TST-010** Coverage target: 90% line AND branch coverage as
  measured by `coverage` with `branch=true` (which is already set in
  `pyproject.toml`).
- **R-TST-011** Per-module coverage reports are produced; modules that
  drop below 90% block CI.

### 22.3 Parallel safety

- **R-TST-020** Tests are run with `pytest -n auto` (xdist). All test
  fixtures are independent: no shared mutable state, no shared cwd,
  no shared output directories. Each test that writes uses
  `tmp_path` (pytest fixture).
- **R-TST-021** XSD-cache scoping in tests:
  - Unit tests that need a cache use a fresh `tmp_path / 'xsd_cache'`
    per test, passed via `xsd_cache_dir` in a per-test config file.
    Each unit test is fully self-contained.
  - Integration tests (`tests/integration/`) share a single
    SESSION-SCOPED cache directory provided by a `pytest` fixture
    (e.g. `tmp_path_factory.mktemp('xsd_cache_session')`). The first
    integration test to need a given XSD downloads it; subsequent
    tests in the same session hit the cache. The same fixture makes
    the directory available to xdist workers via its standard
    `tmp_path_factory` shared-base mechanism so cache hits work
    cross-worker.
  - The shared user-platform cache (`platformdirs.user_cache_dir`) is
    NEVER touched by the test suite.

### 22.4 Live network for XSDs

- **R-TST-030** Integration tests run by default against a pre-seeded
  XSD cache (the seed files under `tests/data/xsd_cache_seed/`, mapped
  by URL in `tests/conftest.py`), so the ordinary test run performs NO
  network access. Tests that exercise a real download from
  pds.nasa.gov carry `@pytest.mark.live` and are opt-in.
- **R-TST-031** The `@pytest.mark.live` decorator marks the opt-in
  tests of R-TST-030 (real XSD downloads) and any future test needing
  network for other reasons.

### 22.5 Fixtures

- **R-TST-040** Test labels and expected outputs are HAND-CURATED for
  the rewrite (per Round 8 user choice). Legacy fixtures in
  `legacy/test_files/` are NOT copied verbatim, but may be referenced
  to construct minimal versions.
- **R-TST-041** Each integration-test bundle directory is kept as
  small as possible while still exercising the targeted feature
  (1–5 labels typical).
- **R-TST-042** Fixtures live under `tests/data/` with subdirectories
  by feature: `bundles/<feature>/`, `configs/<feature>.yaml`,
  `expected/<feature>/{index.csv,index.lblx}`.

### 22.6 Assertion style

- **R-TST-050** Every assert tests exactly one condition; no `and` in
  asserts (per `python_best_practices.mdc` §7.3).
- **R-TST-051** Tests that exercise exception paths use
  `pytest.raises(...)` as a context manager AND assert on the message
  content (per `python_best_practices.mdc` §7.3).
- **R-TST-052** Tests assert exact expected values, not ranges or
  existence checks. Golden-file comparison (`compare_files`) is
  preferred for long outputs (CSV and label files).
- **R-TST-053** No test relies on file-system iteration order; every
  comparison uses sorted lists or stable canonical orderings.

### 25.1 Cross-reference discipline

- **R-DOC-001** Every mention of a class, function, module, attribute,
  or data constant in narrative prose uses the appropriate Sphinx role
  (`:class:`, `:func:`, `:mod:`, `:attr:`, `:data:`). Bare CamelCase or
  inline-literal references are violations of `documentation.mdc` §5.
- **R-DOC-002** Renames or removals MUST be reflected in all docs in
  the same change.
- **R-DOC-003** README badges and quickstart are kept synchronized with
  the docs.

### 25.2 Docstring discipline

- **R-DOC-010** Every public class, function, and method has a
  Google-style docstring with `Parameters:` (NOT `Args:`) and where
  applicable `Returns:` and `Raises:`.
- **R-DOC-011** Docstring lines wrap at 90 characters.
- **R-DOC-012** Docstrings are detailed enough to write a black-box
  test from the docstring alone.

## 26. Future issues

| ID | Title | Current placeholder behavior |
|---|---|---|
| F1 | Quote (`"`) characters in scraped values | Variable-width: hard error. Fixed-width: passed through. Final policy TBD. |
| F2 | Non-ASCII content in scraped values | Hard error. Final policy may be: detect UTF-8 vs ASCII per-column, write `UTF8_*` PDS4 types where appropriate, and use byte (not codepoint) lengths in the label. |
| F3 | Leading/trailing whitespace inside values | Stripped + collapsed. Some PDS4 types preserve whitespace; revisit when those appear in real bundles. |
| F4 | `value_offset` and `field_format` in fixed-width label | Currently omitted. Revisit if PDS Engineering Node validation requires. |
| F5 | Bundle-relative XSD lookup | Currently every label downloads from the URLs it declares. Revisit if a project ships local XSDs and wants to point at them with config. |
| F6 | LID/LIDVID auto-derivation for the generated index label | Currently the user supplies the literal LID in `label_contents.logical_identifier`. Revisit if a templated form (`{stem}` substitution) becomes useful. |
| F7 | Streaming mode for very large bundles | Currently the row list is built fully in memory. Revisit when memory pressure becomes a real problem. |
| F8 | Fixed-width columns whose every value is empty (`field_length = 0`) | Currently emitted as a zero-byte field producing back-to-back commas (R-CSV-073). Some PDS4 validators may reject `<field_length>0</field_length>`. Final policy may be: error out, omit the column, or pad to a 1-byte minimum. Decide once a concrete validator complaint arises. |

Each future issue is also tracked as a GitHub issue once the repo is set
up; the F-IDs above are stable references in this spec.
